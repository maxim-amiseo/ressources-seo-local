Lire le code d'une page avant de la juger : trois points à noter

Quand un site surprend, la première question utile est simple : qu'est-ce qu'il charge réellement ? Un clic droit, « afficher le code source », et en trois minutes on sait si la page repose sur une image, une animation CSS, un script, ou un service externe. C'est le même réflexe qu'un audit sérieux de site professionnel : on lit avant de juger.

Prenons un cas extrême, une page qui ne contient presque rien. Un fond uni, une seule animation, aucun menu, aucun formulaire. Ce type de page se lit en quelques secondes : le poids total tient en quelques dizaines de kilo-octets, aucun script tiers n'est appelé, et le temps d'affichage ne dépend que du réseau du visiteur. On y voit aussi ce qu'il manque pour un site d'entreprise : pas de titre pensé pour la recherche, pas de description, pas de texte que Google pourrait lire.

Cet écart est instructif pour une PME. Un site vitrine n'a pas besoin d'être aussi nu, mais il gagne à garder la même discipline : un titre par page qui répond à la recherche, un texte réel plutôt qu'une image de texte, des scripts limités à ce qui sert à l'affichage ou à la mesure. Chaque ressource chargée en plus ralentit le premier affichage sur téléphone, là où se jouent la majorité des visites.

Pour s'entraîner, le plus simple est de lire le code d'un site que l'on connaît mal et de noter trois choses : le nombre de fichiers chargés, la présence d'un titre et d'une description, et la taille des images. l'analyse du code de Rank-by-ping montre cette lecture appliquée à une page volontairement minimale, avec le code commenté et la date du relevé.
